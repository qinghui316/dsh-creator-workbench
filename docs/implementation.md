# 模块边界与演进

Stage A 保留单个 DSH 插件。宿主入口、界面调用业务操作，业务操作调用文件与宿主适配；纯共享模块不反向引用服务或界面。

| 模块 | 职责 |
| --- | --- |
| src/catalog.ts | 目录扫描、内容状态、产物发现 |
| src/videoSelection.ts | 浏览器与服务端共用的文件名、候选选择与当前路径规则 |
| src/videoFiles.ts | 普通文件、相对文件名与目录范围校验 |
| src/videoImport.ts | 临时文件、可取消复制、无覆盖提交、宿主 Jobs 适配 |
| src/service.ts | Remote 装配、目录与状态协调、会话外业务操作 |
| src/publishRules.ts | 发布状态纯判断与解码 |
| src/publishStatus.ts | 发布状态文件读取与兼容导出 |
| src/client/VideoPanel.tsx | 本机文件选择、重名修改、任务状态、当前视频与播放 |
| scripts/check-dependencies.mjs | TypeScript AST 依赖图、运行时循环、浏览器与纯模块边界 |

当前视频选择存为资料库绝对路径 → 内容 id → 相对文件名。内容切换不会以修改时间换源。预览、字幕与封面启动从同一选择规则取得视频。
新 Remote：startVideoImport、getVideoImport、cancelVideoImport、selectVideo。导入与选择请求携带内容目录，拒绝来自旧资料库界面的请求。

复制先建立独占 .import-UUID.partial，流复制与校验完成后通过同目录硬链接无覆盖提交，再清理临时文件。目标文件系统须支持硬链接（Windows 常用 NTFS 支持）；不支持时返回失败，原文件保留。应用中断留下的点开头 partial 不会被识别为视频，不会自动删除不属于当前任务的文件。
提交后若状态保存失败，完整视频仍保留，用户刷新后可以重新选择。应用重启后可从片库恢复完整产物；未完成任务不自动重试。

宿主 Jobs 管理导入生命周期，没有独立调度器。取消发生在文件提交前会清理本任务临时文件；提交后保留完整产物。后台任务终态查询保留最近记录，上限 100 项，运行中的任务不淘汰。

后续封面、文章与发布模块仅通过内容目录、明确选定的视频、配置和任务结果协作。本阶段保留这些上游能力，进一步拆分在对应阶段完成。

## Desktop 0.12.1 依赖迁移告警（2026-10-23）

本机的“依赖迁移校验失败”来自 Desktop 的迁移校验与实际宿主依赖位置不一致。当前创作工作台已经安装并加载，视频资料仍可打开；Desktop 回退到原来的安装方式继续运行。**迁移尚未成功，告警仍存在。**

定位证据：

- Desktop 的 `installGeneration` 会删除独立代目录内的 `@deepseek-ai/*`、React 等宿主单例，这是宿主的预期行为。
- 随后的 `verifyGenerationPeers` 从插件目录解析依赖，默认认定宿主依赖位于 `DSH_HOME/profiles/node_modules`；本机不存在这个旧回退目录。依赖实际位于 Desktop 的 `resources/app.asar/node_modules`。
- Desktop 主程序的迁移调用未传 `dshEntryPath`。即使只补传该参数，校验器仍先从插件目录解析，失败后直接报缺失，尚未使用宿主锚点，因此也不能通过。
- 对当前已安装产物直接调用原校验器，复现 16 项缺失；所有这些依赖均可从运行中的 Desktop 安装位置解析。在独立诊断进程的内存副本中，只让宿主单例从该安装位置解析，并保留原有闭包检查与依赖遍历，结果为通过、0 项问题。原工作台也复现同样的 16 项缺失，并通过同一对照检查。
- 当前工作区、已安装目录、迁移代目录的清单和四个构建产物 SHA-256 全部一致，排除了安装了旧文件或包中缺少构建入口的解释。

保留只读复现入口 `scripts/diagnose-desktop-migration.mjs`。用目标 Desktop 的 Electron Node 模式运行，参数依次为 resources、DSH_HOME 和待验证代目录；输出原校验、宿主锚点对照及内存副本对照。脚本不安装包、不修改 Desktop、配置或代目录，内存对照不代表生产修复。其他 Desktop 版本需要重新核对实现。

当前包继续按[官方开发规范](https://dshdesktop.com/workbench/docs/development.md)声明宿主 peer 依赖。此告警没有证据支持工作台侧的运行包修复；不将必需依赖标成可选，不私带第二套宿主代码，也不在插件加载时修改迁移校验环境。应由 Desktop 修复迁移调用与解析方式的一致性，再进行实际迁移验收；宿主修复后，原工作台之前出现过的 registry 404 也需独立复查，不能把本次对照通过当作整个迁移已经成功。

本轮仅补充诊断脚本和交接说明，继续使用已验证的 0.1.0 安装包，没有生成或重新安装业务包。既有视频导入、取消、切换与重开证据保存在阶段 A；本轮重新核对包校验、安装文件一致性及 Desktop 重启后的实际加载。模型尚未选择，Agent 模型调用仍未验证。
